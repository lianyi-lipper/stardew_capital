# 01 · 玩家体验与理想表现

[返回目录](README.md) · [下一页：价格形成](02-price-formation.md)

> 以下是目标体验和可用于测试的情境，不是已经运行出的模拟结果。所有报价、持仓和情节数字均为说明用示例。

## 1. 玩家在这里扮演什么角色

玩家可以是需要稳定收入的生产者、分析新闻的投机者、提供流动性的挂单者，也可以在后期成为跨市场交易者。这些不是互斥职业，而是同一账户在不同时间的行为。

种地不是期货交易的门票；期货也不应该是无条件优于种地的自动提款机。农场提供产出与经营风险，金融市场提供另一种收益和风险来源。两者能关联，但不必要求玩家每天盯盘才能正常经营。

判断设计是否成功，不是看曲线是否热闹，而是看：**玩家改变订单以后，市场结果是否随之改变，而且这种改变能由订单、资金和信息解释。**

## 2. 一个普通交易日应是什么样

### 开盘前

终端显示昨结、最近成交、已发布新闻、账户可用资金、保证金和距离到期的天数。玩家可以看到明确的市场状态：尚未开盘，而不是看到一条仍在“偷偷交易”的曲线。

NPC 根据过夜新闻、库存需要和既有仓位调整估值。开盘报价可能与昨日不同；但“指示报价”不能冒充已经成交的开盘价。第一个真实成交才产生开盘成交价。

首次版本采用连续交易开盘；集合竞价作为后续扩展，不与基础撮合同时实现。

### 盘中

平静时会有小额成交，也会有短暂的无成交。价差较窄，挂单分布相对稳定。新闻或大单出现后，部分参与者撤单、改价，部分继续等待。

玩家离开终端去浇水，市场仍按同一游戏时钟运行。打开界面不会召唤更多 NPC；切换图表不会改变行情；无成交期间不会为美观补造价格跳动。

### 收盘后

终端给出当日成交汇总、结算价、结算依据、盈亏结转和风险变化。日内订单按规则失效，允许延续的订单保留其约定期限。休市不撮合，但可以登记下一交易时段生效的指令。

新闻可以在休市期间发布，影响下一次报价；不能直接生成一笔无人交易的“盘后成交”。

## 3. 套期保值：收入更稳定，不代表过程没有风险

示例：预期获得 1,000 个防风草，每手 100 个。玩家以 40g/个卖出 10 手期货。

在理想化的同标的、同数量、同交割时点和相同现货基准条件下，忽略费用：

| 到期现货/结算指数 | 卖出作物收入 | 空头期货累计盈亏 | 合计 |
|---|---:|---:|---:|
| 25g | 25,000g | +15,000g | 40,000g |
| 60g | 60,000g | −20,000g | 40,000g |

实际游戏必须允许这张表不完全成立：产量可能不足，品质不同，地方收购价与指数不同，卖货时间不同，还存在交易成本。UI 应显示“计划套保数量、实际库存、未覆盖数量、指数与当地报价差”，而不是宣称保证获得固定收入。

更重要的是，涨到 60g 时作物可能尚未收获，期货却已经需要补充资金。玩家最终可能判断正确，却因为中途资金不足被迫平仓。这是期货风险管理的重要体验，不应由系统免除。

**阶段边界：** 首次独立沙盒只能验证账户和结算；接入真正的农场产出、动态出售报价之后，才能称为实际农场套保。原版固定售价仍有效时，不能把上述例子当作已实现玩法。

## 4. 同一条新闻，不必只有一种结果

新闻：“周边农场遭遇虫害，预计本季产量下降。”

合理的因果过程：

1. 事件改变部分地区、部分作物的预期供给；其影响范围不是所有商品。
2. 采购商担心未来成本上升，逐步增加买入套保；受灾生产者可能撤掉原先的卖出套保订单，因为可交付产量变少。
3. 做市商调整估值和报价，必要时减少卖盘深度；趋势交易者通常在观察到实际上涨后才行动。
4. 新的买单与卖单成交，形成新的行情。

最终可能上涨、过度上涨后回落，也可能几乎不动：例如消息已被预期，仓库存货很多，或者另一条进口消息抵消短缺。

新闻页说明事实、发布日期、影响范围和不确定性，不显示“系统安排接下来涨 12%”。解释面板可以说“新闻发布后卖盘深度下降”，不能把模型内部的估值当作玩家可知真相。

也不要求所有消息都缓慢消化。撤单后盘口出现空档，真实成交可以跳到更远价格。**允许跳空，不允许没有订单依据的瞬移成交。**

## 5. 扫单：自己制造的上涨不是自己的利润

某时刻卖盘如下，价格单位为 g/个，数量单位为手：

| 卖价 | 数量 |
|---:|---:|
| 40.01 | 2 |
| 40.02 | 3 |
| 40.05 | 5 |

玩家买入 10 手并接受 40.05 的最高价，全部成交的均价是 40.033，最后一笔成交价是 40.05。玩家确实吃掉了低价卖盘，但不能据此断言已有可兑现盈利：立即卖出要面对买盘，可能跨过价差并产生新的滑点。

若玩家保护价为 40.03，只能立即成交前 5 手，剩余 5 手取消。终端应反馈“部分成交 5/10；剩余因价格保护取消”，不能默认无限流动性补齐。

成交量、均价、手续费、当前可退出的深度都需要展示。未实现盈亏使用风险标记价；预计退出收入基于买卖盘估算，两者也不应混淆。

## 6. 挂单墙：可以承接市场，但不是免费护盘

玩家在 40g 挂出 100 手买单。随后有 60 手卖单打到这一价位：玩家实际买入 60 手，剩余挂单 40 手，对应保证金继续被预留。

只要该价位的有效买单仍在，卖方不能越过更好的报价去更低价成交。但这不保证墙永远存在：它可能被吃完、被玩家撤回，或因为账户风险而被取消。

合理表现：

- 盘口显示剩余数量递减，成交记录显示真实成交，持仓同步增加。
- 挂单越大，占用越多账户资源；吃到越多，承担的持仓风险越大。
- 后续价格继续下跌时，护盘者会亏损，而不是只获得“市场影响力”。

第一版 NPC 不因看到大墙就无条件跟风。后续需要加入盘口心理时，只把持续存在、有成交支持的深度作为弱信号，并限制影响，避免反复挂撤巨单就能无成本操纵所有 NPC。

## 7. 趋势、泡沫和恐慌如何出现

目标是让它们成为可能发生的结果，不是每季必须播放的剧情。

| 现象 | 希望看到的行为链 | 不允许的实现捷径 |
|---|---|---|
| 趋势延续 | 持续订单流 → 成交上涨 → 趋势者增加买入 | 每 tick 自动给价格加正数 |
| 短期泡沫 | 追涨者增仓、价值卖方资金有限、流动性下降 | 抽到“繁荣剧本”就指定翻倍 |
| 恐慌 | 风险升高 → 买盘减少 → 卖出滑点 → 风险进一步恶化 | 一条新闻同时强制所有价格跌停 |
| 轧空 | 上涨使空头保证金不足 → 强制买入 → 进一步吃掉卖盘 | 把价值交易者的系数改个符号 |
| 流动性枯竭 | 做市商达到风险上限，盘口变薄甚至单边 | 无限生成对手单来维持画面热闹 |

有限规模的规则系统不保证自然重现真实市场的所有统计特征。是否真的出现这些现象，要通过多随机种子实验、账户记录和消融测试验证，不能靠挑选一条好看的曲线宣布成功。

## 8. 到期日不是“价格被磁铁吸回去”

临近到期，持有较大仓位的交易者会考虑资金和结算，交易者的估值可能更接近预计结算指数。能够真正进行现货与期货交易的参与者，也可能减少不合理价差。

但资金、库存和流动性限制意味着最后成交价不必在每一秒都等于现货。交易结束时按公开合约规则计算最终结算价，结转盈亏并关闭合约。

UI 分别保留：最后成交价、最终结算价、结算时间、结算来源和账户结转金额。两者不同时，解释价差；不得补造一笔最终结算价的成交，也不得把它算入成交量。

## 9. “可理解”比“看起来专业”更重要

每个重要状态都应有一句可操作说明：

| 状态 | 玩家能理解的反馈 |
|---|---|
| 限价未成交 | 你的买价低于最低卖价；订单仍在排队 |
| 部分成交 | 已买入 3 手，剩余 2 手继续排队/已取消 |
| 风控拒绝 | 新订单需要预留 600g，目前可用 480g |
| 数据不足 | 最近没有成交；当前显示的是报价，不是成交价 |
| 保证金警告 | 当前权益低于维持要求；请补充资金或减少仓位 |
| 强平中 | 系统正在按保护价格减仓；不保证立即成交 |
| 无法退出 | 当前没有足够对手盘；可调整限价，但可能扩大损失 |
| 到期完成 | 合约按已公布指数现金结算；不是卖出了实际作物 |

玩家终端解释自己的订单、持仓和公开市场。开发者观察台解释完整因果链。两种视角必须分开。

## 10. 首个可玩版本的成功标准

玩家能够连续完成：读取新闻 → 判断方向或安排套保 → 选择订单 → 观察成交/未成交 → 看懂资金与持仓变化 → 处理风险 → 平仓或到期。

同一初始状态和同一随机种子下，有玩家大单与没有该订单的两次实验应出现可归因的差异；而仅打开/关闭 UI 不应产生差异。市场不必一直热闹，但必须能解释并承担每笔交易的后果。
