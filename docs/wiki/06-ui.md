# 06 · UI 与可观测性

[返回目录](README.md) · [上一页：运行性能](05-runtime-and-performance.md) · [下一页：重启路线](07-roadmap-and-tests.md)

## 1. 结论：需要更新，但不是只换配色

当前 main 的 [`StardewCapital.Tests/price_viewer.html`](../../StardewCapital.Tests/price_viewer.html) 是离线 JSON 价格查看器，已有商品选择、季节价格、日内曲线、模型参数和新闻列表。它适合观察旧价格生成器，但不承担完整交易、账户和风险交互。

未来应分成两个视角：**玩家交易终端**与**开发者市场观察台**。两者共享图表和只读快照基础，不共享默认信息权限。

当前仓库基线未包含完整的游戏内菜单代码；本地或历史版本中如仍有旧菜单，接入时另行检查。以下是信息架构与交互规范，不是已经完成的 UI 改版。

## 2. 玩家终端首先回答五个问题

我在交易什么？现在能以什么价格成交？我有哪些订单和仓位？我还有多少风险承受空间？发生了什么新信息？

相较之下，GBM 参数、隐藏基本面真值、每个 NPC 的余额和策略权重，都不应占据玩家首页。

### 桌面布局草案

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 星露资本   交易中 · 第2年春3日 10:20      账户权益 / 可用 / 风险状态   │
├──────────────┬──────────────────────────────────┬───────────────────┤
│ 合约列表     │ 防风草·春季   每手100个   距到期25天 │ 买卖盘 / 最近成交 │
│ 价格、价差   │ 最新成交 / 风险标记 / 昨结 / 指数   │ 价格、数量、深度  │
│ 流动性状态   │                                  │                   │
│              │ 成交图 + 成交量 + 新闻标记        │ 下单面板          │
│              │ 时间范围、缩放、公开叠加线        │ 方向 / 类型 / 数量│
│              │                                  │ 价格 / 保护价     │
├──────────────┴──────────────────────────────────┴───────────────────┤
│ 持仓 | 当前订单 | 成交记录 | 资金账单 | 新闻 | 合约规则                │
│ 明确显示：数量、均价、盈亏、占用、状态、失败原因及可操作按钮           │
└─────────────────────────────────────────────────────────────────────┘
```

这是结构示意，不是像素级设计。桌面可从 1280×720 的有效可用空间验证；小空间采用“行情/交易/账户/新闻”分页，而不是把所有文字缩小到难以阅读。

## 3. 合约与行情区

合约列表显示商品名、交割年月/季节、最新成交、买卖价差、成交量和市场状态。不同年份不能仅显示同一个 `PARSNIP-SPR-28`。

选中合约后始终保留：报价单位、每手乘数、最小跳动、到期时间、结算方式、交易时段、保证金率和规则入口。

最新成交价旁显示最后成交时间。没有成交时显示“尚无成交”；报价陈旧时显示时间和警告，不用模型目标价填充空缺。

风险标记、昨结、现货指数使用各自标签和解释。不默认同时显示大量折线；默认一条成交曲线，指数与标记价由用户选择叠加。

## 4. 图表不能制造不存在的市场

成交图和 OHLC 只依据真实成交事件。无成交时间段保留缺口或明确的延续参考线，成交量为零。报价中间价可以单独画，但必须标为报价，不能与成交 K 线混用。

到期结算和日结用专门标记展示，不补造一根最后成交 K 线。回放模式中的未来数据对玩家视角不能提前暴露；完整离线数据仅在研究视角可见。

旧查看器的平滑曲线可以保留作 Legacy 展示。新交易图默认不做会暗示虚构极值的样条平滑，提示框只落在真实采样/成交位置。

在价格轴和数量轴明确区分 g/个、手、实物单位。图表至少支持价格、成交量、新闻时间点、自己的成交标记和当前订单价位；指标库以后再增加。

## 5. 盘口与逐笔成交

首版显示前 5 档或 10 档聚合盘口：价格、总手数、对应实物量、累计量。自己的挂单高亮，显示自身剩余量；不必暴露所有 NPC 身份。

盘口点击可以填入下单价格，但不能直接提交。数量和价格输入在用户编辑期间不被行情更新覆盖。

盘口无买方、无卖方、价差过宽、深度不足时有明确状态。最后成交价保持不动而报价变化是正常情况，界面不应“修正”为两者一起跳。

最近成交列表显示时间、价格、手数和可确定的主动方向。不能仅凭涨跌颜色就猜测真实买卖发起方；方向数据应由撮合事件提供。

## 6. 下单面板

首版支持限价与带保护价的快速成交 IOC。表单字段：买/卖、手数、价格或最差可接受价、订单期限、仅减仓开关。

下单前预览：名义规模、预计初始保证金、预计费用、对当前净仓位的影响、基于当前盘口的可成交量/均价估计，以及成交后剩余可用资金估计。

预览不是成交承诺。提交时再验证，行情改变导致结果不同要说明。大额、反手、接近到期、显著扩大风险的操作使用额外确认；普通小额操作不层层弹窗。

“买入”不必然等于开多，“卖出”不必然等于开空。表单应解释例如“先平空 2 手，再开多 1 手”。仅减仓开启时不能反手。

命令使用唯一 ID，连续点击或网络重试不能重复下单。提交后显示 Pending，收到交易所确认才显示已接受；不能点击后先假设成交，再用失败提示回滚画面。

## 7. 订单与持仓必须有状态，而不是只有数字

### 订单

至少区分：待确认、已接受、部分成交、全部成交、撤单待确认、已撤销、已过期、已拒绝、IOC 剩余取消。

每行保留原始数量、累计成交、剩余、限价、预留资金和最近原因。撤单按钮只操作剩余量。已部分成交的订单即使剩余取消，仍保留其成交记录。

### 持仓

显示净手数、原始交易均价/历史入口、当前结算成本基准、标记价、未实现盈亏、累计已实现盈亏、手续费、保证金要求和到期倒计时。

日结后成本基准改变，说明“已按结算价结转”，而不是让用户误以为均价记录错误。预估强平价只能在模型支持且假设明确时显示；多合约或动态标记下不能给出一个虚假的精确数字。

### 风险状态

警告使用“当前权益/维持要求/缺口/处置期限”四个明确量，不只用一条抽象百分比进度条。

强平中显示已经执行的数量、剩余数量、价格保护和当前不能成交的原因。无流动性时显示“尚未完成减仓”，不得把排队指令显示为已经清仓。

## 8. 新闻、说明与账单

新闻卡片包含发生/公开时间、影响地区与商品、事实描述、来源/可靠度和后续更新。与游戏背景相符的叙事可以保留，但核心信息需要一眼可读。

价格变化解释只引用已观察到的事实，例如“公告后 15 个游戏分钟内，卖盘前五档深度下降、主动买入增加”。多因素市场不应输出“已确定是某新闻造成上涨”的虚假单因果解释。

资金账单按事件展示存款、提现、费用、平仓盈亏、日结、最终结算和风险处置。点击可关联订单/成交/规则版本，使玩家能追溯余额变化。

首版帮助采用固定文本与规则解释，无需运行时大模型。

## 9. 开发者观察台：保留旧工具的价值

不要把 `price_viewer.html` 删除后另起一套无关工具。它可以逐步升级为研究观察台，保留旧 JSON 导入，并明确标记 `Legacy price-path`。

新模式额外需要：

| 页面 | 用途 |
|---|---|
| 价格与盘口 | 并列查看成交、买卖报价、指数、风险标记与结算 |
| 代理观察 | 各类型资金、持仓、目标仓位、订单及决策理由 |
| 事件时间线 | 事件→观察→订单→成交→风险的关联 ID |
| 对账 | 净持仓和、现金守恒、费用、预留与违约余额 |
| 性能 | 逻辑步耗时分位数、事件积压、订单数、分配与内存 |
| 实验对比 | 相同事件下有无玩家订单、有无某类代理的差异 |

研究端可以看隐藏经济状态，也可暂停、单步、修改实验参数。必须有显眼“研究/上帝视角”标记；这些功能不是正式游戏中的默认交易权限。

离线回放不能伪装成实时交易。历史 JSON 导入后，下单控件禁用并注明原因。后续接入实时 Core 时，才经命令接口发送交易指令。

## 10. 数据接口与版本

UI 只接收 `PublicMarketSnapshot`、`OwnAccountSnapshot` 和事件；研究端额外接收 `DebugSnapshot`。公共快照中不要包含未来目标价，再寄希望于前端不显示它。

建议最小公共快照字段：

```text
schema_version, simulation_id, sequence, sim_time, market_status
instrument_id, currency, price_scale, tick_size, contract_multiplier
last_trade_price?, last_trade_time?, best_bid?, best_ask?
spot_index?, index_time?, risk_mark?, risk_confidence
previous_settlement?, daily_volume, open_interest
book_levels[], recent_trades[], published_news[]
```

账户快照单独包含账户权限范围内的现金、权益、可用、预留、风险、订单和持仓。`sequence` 用于识别重复/过时消息；缺失价格使用空值，不用零值。

旧文件没有新字段时按旧 schema 读取，不自动把 `shadowPrice` 当成成交价。新导出器可以另开格式版本，旧查看器保留兼容读取入口。

首版不必引入大型前端框架。独立观察台可以沿用 HTML/JavaScript，游戏终端使用适合目标游戏的 UI；两者通过共同快照语义保持一致，不强求相同渲染技术。

## 11. 可用性与性能要求

报价更新不能移动按钮或夺取输入焦点。红涨绿跌/绿涨红跌可配置，同时显示正负号和文字，不只靠颜色。

支持键盘导航、清晰焦点、中文长文本、UI 缩放和较小屏幕。告警分级：普通成交不弹强干扰窗口；保证金危险与交易暂停需要明显通知。

图表数据 2—4 次/真实秒更新即可作为初始预算；绘制可使用缓存。隐藏面板停止绘制，不停止市场。长记录分页/虚拟化，不每帧构造全部历史。

外部新闻/配置文本作为文本渲染，不直接插入可执行 HTML。未来研究台如增加本地网络桥接，需要独立鉴权和暴露范围设计；第一版不为一个单机 UI 默认开放公网端口。

## 12. 更新优先级

**第一步：** 在研究查看器里增加盘口、真实成交、事件时间线和对账状态，先能看懂市场。

**第二步：** 增加独立沙盒交互终端，完成下单、撤单、持仓、保证金、账单和公开规则。

**第三步：** 验证非暂停游戏适配，再做星露谷风格外观、手柄/分屏和经营系统整合。

股票、外汇、基金暂不出现大量灰色空标签。先保留导航扩展点，不把未来愿景变成当前界面的负担。

验收重点：新玩家能独立完成交易闭环；开发者能追溯每次异常；看界面不会改变模拟结果。外观美化排在这三件事之后。
