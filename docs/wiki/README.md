## 项目究竟要做什么

**做一个可以独立运行、也可以接入《星露谷物语》的金融经济模拟系统。先把商品期货市场做完整，再让股票、外汇、基金和银行接入同一个经济世界。**

目标不是让曲线更像股票软件，也不是给农场增加一个随机赚钱按钮。目标是让有不同目的、不同信息和有限资金的参与者真正交易，让成交、持仓、经营活动和风险相互影响。

玩家应当能回答：我为什么成交在这里？为什么挂单没成交？为什么判断方向正确却仍然亏钱？这次波动是供需变化、流动性减少，还是有人被迫平仓？

本方案不要求大模型、强化学习训练、独显、云服务、数据库或每个 NPC 一条线程。第一阶段的“智能体”是带账户、状态和简单决策规则的小对象。

## 十条不可破坏的设计原则

1. **成交价只能由真实撮合产生。** 模型可以影响报价意愿，不能跳过交易所改写最后成交价。
2. **交易必须有双方、有账户、有资源约束。** 做市商不是无限现金的兑换机，NPC 也会亏损、减少仓位或退出。
3. **有挂单不等于成交，有成交不等于没有风险。** 允许部分成交、拒单、空盘口和交易暂停。
4. **基本面、参与者估值、现货指数、成交价、风险标记价、结算价分开。** UI 不把它们统称为“价格”。
5. **新闻改变事实和认知，不直接写入涨跌幅。** 可以出现跳空，也可以被提前预期、被质疑或被其他订单抵消。
6. **没有预定收盘路径。** 日内不会为了画面好看而强制收敛；到期按公开规则结算，不伪造成交。
7. **同一撮合、资金和风险规则适用于玩家与 NPC。** 内部调试权限不等于交易特权。
8. **界面不是市场时钟。** 打开面板、切换商品、改变帧率不能改变市场演化。
9. **小规模、可解释、可回放优先。** 先把一个商品做对，再增加参与者、品种和宏观系统。
10. **新方案与旧方案显式分离。** 不在同一市场同时运行旧价格生成器和新撮合定价，避免出现两个价格权威。

## 一张逻辑图

```text
生产、消费、库存、贸易与事件
           ↓
经济状态 ──→ 可公开的现货指数 / 新闻 / 经营信息
           ↓                  ↓
     各参与者不同的观察、信念和风险预算
                         ↓
                 撤单、改单、提交订单
                         ↓
                风控预检 → 订单簿撮合
                         ↓
             成交记录 → 账户与持仓 → 风控
                ↓                     ↓
             公共行情              被迫减仓订单
                └────────反馈────────┘
```

这里的箭头表示数据和决策依赖，不代表每一层每帧都运行一次。

## 建议的首次可玩范围

一个防风草现金结算期货合约；12 个规则型 NPC 起步；确定性订单簿；独立交易账户；限价单和带保护价的立即成交订单；持仓、保证金、日结、到期结算；一个能显示盘口、成交、订单和风险的终端。

**现金结算是阶段选择，不是否定最终的实物交割。** 在库存、品质、仓储和交收系统完成以前，不宣称已经支持完整期现套利或精确农场套保。详见 02、04。

默认配置的下一档目标是全市场合计 32 个逻辑参与者、最多 3 个活跃合约。此时仍不开发股票、外汇、基金或中央银行。

## 文档如何维护

- 本 Wiki 描述目标架构；“已实现”状态以代码和自动化测试为准。
- 根目录的旧《期货参考文档》《模型公式更新》《参考资料》保留为历史设计，不删除、不伪装成新方案的实现记录。
- 新架构实现时，遇到冲突以本 Wiki 的决策为新模式目标；旧模式仍可保留作独立对照实验。
- 每个里程碑完成后，在 07 的验收表记录提交、测试输出、性能测量和未解决问题，而不是仅打一个完成勾。
- 参数是实验起点，不是经济学常数。改变默认参数、结算规则或时钟语义时，必须提升配置/规则版本，并给出迁移说明。
