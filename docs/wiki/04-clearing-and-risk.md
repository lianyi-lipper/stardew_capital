# 04 · 清算、账户与风险

[返回目录](README.md) · [上一页：智能体](03-agents.md) · [下一页：运行与性能](05-runtime-and-performance.md)

> 这是交易市场成立的前提，不是最后才补的附属功能。只检查“余额够不够下第一单”不足以形成期货系统。以下为游戏设计；真实期货的逐日盯市、保证金与交割机制参见 [来源 R3—R5](09-sources.md)。

## 1. 首版账户边界

玩家将游戏钱包中的金币转入独立交易账户。第一版不自动拿玩家全部钱包、土地或物品作担保，也不自动贷款。

NPC 同样使用真实账户。交易所、手续费账户、清算保证基金和外部经济部门各有明确账目。交易账户之外的资金注入、提现和经营收入必须形成双边转账事件。

首版一个账户可以对多个期货合约做净额持仓，但不做复杂跨品种保证金抵扣。所有合约的风险需求保守相加。将来要支持组合抵扣，必须新增模型版本和压力测试，不能直接把不同资产的多空手数相抵。

## 2. 金额、价格和数量的表示

实际账本不用二进制浮点累计金币。建议使用最小货币单位的 `long` 与价格 tick 整数；策略估值和统计可以使用浮点数，提交订单前必须转换并验证。

例如报价 tick 为 0.01g/个、每手 100 个，则每手移动一 tick 的盈亏为 1g。定义最小货币单位为 0.01g 时，这笔盈亏是 100 个最小货币单位。

合约 tick、乘数和币种精度必须兼容。不能整除的结算值使用明确的舍入规则，对账差额进入专门舍入账户，不偷偷消失。金额乘法需要溢出检查。

内部可以保留分币，游戏钱包只显示/接收整数金币时，零头继续留在交易账户，不因反复存取款产生舍入套利。

## 3. 必须分开的账户字段

| 字段 | 定义 |
|---|---|
| `CashBalance` | 已实际入账的现金，包含已经结转的盈亏 |
| `UnrealizedPnL` | 按共享风险标记价计算、尚未结转的盈亏 |
| `Equity` | 现金 + 未实现盈亏 |
| `PositionInitialMargin` | 当前持仓初始保证金要求 |
| `WorkingOrderMargin` | 尚未成交订单可能增加敞口所需的额外预留 |
| `FeeReserve` | 挂单可能发生的费用预留 |
| `AvailableForNewRisk` | 权益扣除持仓要求、挂单预留、费用和其他合法冻结后的可用额 |
| `WithdrawableCash` | 同时受实际现金、风险要求和提现冻结约束的可提现额 |

保证金是资金占用，不是把合约名义本金支付给对手方，也不是凭空增加一笔资产。取消订单释放的是预留；只有发生交易、结转或转账，才改变实际现金。

未实现盈利可以如何支持新仓，必须配置并公开；首版提现不允许把未结转盈利当作已经到账的现金。

## 4. 持仓与盈亏

每个账户、每个合约维护一个有符号净持仓 `q`：多头为正，空头为负。还需要记录当前结算成本基准、已实现盈亏、费用、可交割数量和关联订单。

对简单同成本持仓：

```text
未实现盈亏 = q × 每手乘数 × (风险标记价 − 成本基准)
```

增加同向仓位时更新加权成本；反向成交先关闭原持仓，再按剩余数量开反向仓位。跨零反手必须拆分两段记账。首版使用净持仓，不同时维护互不抵扣的多空双仓。

### 一个完整账务例子

忽略手续费，初始现金 1,000g，买入 2 手，乘数 100，开仓价 40g：

| 时点 | 现金 | 净持仓 | 成本基准 | 未实现盈亏 |
|---|---:|---:|---:|---:|
| 以 40 买入 2 手 | 1,000 | +2 | 40 | 0 |
| 风险标记价变成 41 | 1,000 | +2 | 40 | +200 |
| 日终按 41 结算 | 1,200 | +2 | 41 | 0 |
| 次日以 42 卖出 1 手，标记价为 42 | 1,300 | +1 | 41 | +100 |
| 剩余仓位按 42 日结 | 1,400 | +1 | 42 | 0 |
| 到期按 43 现金结算 | 1,500 | 0 | 无 | 0 |

累计盈利是 500g，不是 500g 再加已经结转的 200g。对应亏损由其他持仓账户通过清算支付，不由系统凭空生成。

每天重设成本基准后，UI 仍应保留原始开仓历史用于解释总收益，避免玩家误以为自己的开仓价被篡改。

## 5. 下单前先占用资源

订单进入交易所前完成：合约状态、数量/价格、账户权限、自成交风险、费用、资金和最坏可成交敞口检查。

限价买单按限价估算最大支付风险；带保护价的快速成交订单按保护价计算，不按已经过时的最后成交价。卖单、开空和可能反手的订单也需要计算保证金，不能因为“卖出能获得钱”而免检。

第一版对多个独立开仓订单采用保守预留：所有可能增加风险的订单都占用资源，不假设其中只有一笔会成交。对挂单墙和做市商双边报价同样适用。

`reduce-only` 订单只允许减少已存在仓位，不能穿过零反手；同一持仓被多笔减仓订单引用时也不能重复允许超量减仓。

**关键测试：** 账户只有 1,000g，不得通过连续挂 10 笔“各自只需 500g”的订单获得 5,000g 的承诺敞口。撤单、部分成交和改价后都要精确更新预留。

## 6. 每笔成交作为一个原子状态变更

```text
验证当前订单与账户仍可执行
  → 确定双方订单、数量、价格和费用
  → 更新双方订单剩余量
  → 更新双方持仓与已实现盈亏
  → 更新/释放双方预留
  → 写入手续费及清算账目
  → 写入唯一成交事件和账本事件
  → 发布新快照，并安排必要的风险检查
```

界面不能观察到“订单已经成交，账户还没扣风险”的中间状态。失败时不留下半笔成交。一个主动订单跨多个对手单时，每笔成交分别原子记账；中途达到保护条件，剩余量取消或继续挂单，按订单规则处理。

同一命令 ID 重发不重复下单，同一成交 ID 重放不重复扣费，同一结算事件不重复结转。

## 7. 保证金与风控状态机

最小模型可先采用线性要求：

```text
初始要求 = |q| × 合约乘数 × 风险标记价 × 初始保证金率
维持要求 = |q| × 合约乘数 × 风险标记价 × 维持保证金率
```

比率属于合约配置，必须满足初始率高于维持率。现有配置中的 10%/8%可以作为回归测试案例，但是否适合可玩版本需根据价格风险、交易频率和强平压力测试决定，不自动认定为合理杠杆。

状态：

```text
Healthy → Warning → MarginCall → Liquidating → Healthy / Defaulted
```

- `Warning`：风险缓冲低于预警线，提示玩家；不必立即强平。
- `MarginCall`：权益低于维持要求，先停止新增风险、取消增加风险的挂单，并给出已配置的补款/减仓窗口。
- `Liquidating`：到达宽限期限，或权益已经低于紧急阈值，按规则提交减少风险的订单。
- `Defaulted`：损失和可执行处置超过账户资源，进入违约流程。

宽限用模拟时间，不用 UI 打开多久计算。所有账户适用同样的规则；紧急破产情境不能为了让玩家来得及点按钮而让亏损无限积累。

## 8. 强平也必须真的成交

强平不是 `position = 0`。风险服务提交 `reduce-only`、带价格保护的分批订单，经过同一个订单簿。

结果可能是成交、部分成交或无对手盘。系统记录剩余敞口、执行价格、滑点与费用。下一轮继续处置时遵循明确的保护区间和优先级，不能循环无限重试，也不能在无流动性时保证按标记价成交。

首版可以按“风险占用最大合约优先、固定批量减仓”降低复杂度，但所有排序和批量参数必须确定化并可测试。未来才考虑组合最优化。

价格涨跌限制、休市、数据失真时必须有独立处置状态。不能同时承诺“不允许超出涨停价成交”和“任何情况下立即清仓”。

## 9. 缺口、违约与清算基金

期货账户可能因跳空和流动性不足出现负权益。第一版不能声称保证金能保证永不穿仓。

建议处理顺序：

1. 停止违约账户主动增加风险，释放无用挂单并处置可执行仓位。
2. 使用该交易账户可用现金承担损失；未结清差额记为明确欠款/损失。
3. 有限规模清算保证基金按规则吸收可覆盖损失，转账真实入账。
4. 基金不足时进入市场级 `DefaultResolution`：停止新增风险，记录债权债务、未结头寸和待分配损失，不继续给盈利方发无限金币。

首次可玩版可以选择清楚展示“交易账户破产，市场进入处置”的失败结局，不必实现复杂的自动减仓/损失分摊。但没有明确处理方式，就不能开放无限杠杆和长期运行。

沙盒中允许用户重置实验，重置必须显式标为新实验。不得暗中恢复 NPC 资金、消除玩家欠款或修改已经发生的交易。

清算基金初始化资金是已记录的外部资本，不是没有来源的余额。基金支出必须能与受偿账户的收入对账。

## 10. 日终、到期与实物交割

### 日终

按 02 的结算规则，对未平仓部分结转变化保证金，重设成本基准、更新风险要求，并保存日终账单。当天已经平仓的盈亏不再次结转。

现实期货逐日盯市与保证金不是本 Wiki 的原创概念；本项目的采样窗口、宽限和账户边界是游戏化选择。[来源 R3、R4](09-sources.md)

### 首版：现金到期

到达最后交易时点后停止撮合，撤销未成交订单，按已公布指数结算剩余持仓，记录双方现金流并将合约设为 `Expired`。指数不可用时进入待结算状态，不让玩家继续交易一张理应到期的合约。

### 后续：实物交割

只有库存适配完成后才开放，并至少明确：可交付品种/品质、仓单、交割地点、截止时间、买方全额货款、卖方货物锁定、运输/仓储费用及违约规则。

已逐日盯市的合约，最后仍需按交割发票价格进行实物货款支付与货物转移；不能把之前已经结转的期货盈亏再算一次。多头准备的是完整货款，不是只交保证金就免费拿货。

未具备交割能力的账户，应在预先公布的截止点前限制开仓或要求减仓。自动减仓仍可能失败，因此必须保留交割违约处置，而不是宣称系统永远能在最后一秒平仓。

## 11. 不可破坏的账本不变量

- 每个期货合约所有账户净持仓之和为零，包括做市商和处置账户。
- 合约总多头手数等于总空头手数；持仓量不能简单等于累计成交量。
- 每笔手续费是交易账户支出和手续费账户收入，不凭空消失。
- 现金变化能由转账、费用、平仓盈亏、结算和正式处置解释。
- 每笔成交的买卖数量相等；一个订单的已成交量与剩余量不超过初始量。
- 挂单预留非负；全部撤销或到期后不残留占用。
- 没有外部资金事件时，封闭系统内净资金变化为零；舍入差额单独记录。
- 无交易但标记价变化时，浮动盈亏可变化，现金不能随每次行情刷新重复变化。

这些检查应在测试环境每步运行。生产版本保留廉价断言和日终对账，发现破坏时停止新增风险并生成诊断报告，而不是继续模拟。
