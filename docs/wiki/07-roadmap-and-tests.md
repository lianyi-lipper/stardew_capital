# 07 · 重启路线与验收

[返回目录](README.md) · [上一页：UI](06-ui.md) · [下一页：扩展基础](08-extension-and-decisions.md)

> 核对基线：`05b52d6e8b5ae3b1bccb9b47450519e6e389b2c5`。以下实现判断来自静态阅读，并未编译、运行或进行性能测试。所有新架构里程碑均为待开发，不能因为文档已提交就标记完成。

## 1. 旧项目不是全部推倒重来

| 当前部分 | 建议处理 | 原因 |
|---|---|---|
| `Common/Market` 订单、接口、撮合器 | 保留概念与可复用逻辑，补确定性和风险测试 | 已有买卖、限价、市价及价格优先结构 |
| `FuturesOrderBook` | 作为迁移起点，不视为完整风控 | 已有初始保证金检查；强平方法仍是占位逻辑 |
| `FuturesMarket` | 保留为旧模式入口，另建新模式编排器 | 当前 Tick 直接调用价格生成器，不是成交驱动市场 |
| `GBM`、`BrownianBridge` | 留在 Legacy 对照模式/独立实验 | 不再决定新模式的成交价或必然收盘价 |
| `CostOfCarry` | 保留为估值工具并核对单位 | 供代理估值使用，不强制所有成交满足公式 |
| `FundamentalEngine`、商品和新闻配置 | 拆出经济状态与信息模型，做显式迁移 | 供需和新闻有价值，但真值、认知、价格需要分离 |
| `Time` | 保留抽象，升级绝对时间与时间转换 | 需要跨年、回放和与 UI 无关的时钟 |
| `SimulationExporter`、`price_viewer.html` | 保留旧格式读取，新增 v2 事件/快照格式 | 研究工具已经存在，不必丢弃 |
| `StardewCapital.Tests/Program.cs` | 保留交互演示，另加自动断言测试项目 | 控制台展示不能替代可重复的测试门禁 |

旧模式和新模式通过显式 `MarketMode`/宿主选择，名称和导出格式都应清楚区分。禁止一个步骤先执行旧价格生成，再运行新撮合“微调”价格。

## 2. 静态阅读发现的迁移风险

这些是应优先编写复现测试的线索，不是已经验证的完整 bug 清单。

### 时间与合约身份

[`SimulationClock`](https://github.com/lianyi-lipper/stardew_capital/blob/05b52d6e8b5ae3b1bccb9b47450519e6e389b2c5/StardewCapital.Core/Time/SimulationClock.cs) 的日间进度使用 HHMM 数值差；应覆盖跨小时边界测试。现有合约 Symbol 不包含年份；新模型需要绝对到期日，避免跨年覆盖和到期合约复活。

### 新闻重复与作用范围

[`FuturesMarket.AddNews`](https://github.com/lianyi-lipper/stardew_capital/blob/05b52d6e8b5ae3b1bccb9b47450519e6e389b2c5/StardewCapital.Core/Futures/FuturesMarket.cs) 先把新闻加入共享基本面引擎，再通知价格生成器；后者的新闻处理也有添加行为。应测试一次事件是否因合约数量而重复累计。

[`FundamentalEngine`](https://github.com/lianyi-lipper/stardew_capital/blob/05b52d6e8b5ae3b1bccb9b47450519e6e389b2c5/StardewCapital.Core/Futures/Pricing/FundamentalEngine.cs) 的简化 `NewsEvent` 转换没有完整保留商品/地区作用范围；`CalculateExpectedValue` 调用计算时未显式传递当前日。新模型应以事件实例 ID 去重，保留范围，并测试时间边界与前视信息。

### 商品关联 ID 与合约 ID

当前关联处理拿 `corrId` 查合约字典，而字典键和配置中的商品 ID 可能不是同一层身份。不能在没有映射测试的情况下宣称跨商品联动已经正确生效。

新模型明确 `CommodityId → 活跃 InstrumentId 集合`，并通过经营需求或代理估值传导，不直接给另一个合约加价格冲击。

### 顺序与可回放

[`PriceTimePriorityEngine`](https://github.com/lianyi-lipper/stardew_capital/blob/05b52d6e8b5ae3b1bccb9b47450519e6e389b2c5/StardewCapital.Core/Common/Market/Engines/PriceTimePriorityEngine.cs) 使用现实时间戳和静态成交 ID；应迁移到模拟时钟与可保存序号。报价刷新、列表排序和同价订单位置需要单独测试，不能只靠类名保证 FIFO。

### 账户与价格权威

当前余额检查不等同于完整资金预留、持仓、结转和强平。新模式成交后仍叠加 `MarketImpact` 会重复计算冲击；日终直接覆盖成交价也与新方案冲突。这些是模式切换边界，不能只调几个参数完成迁移。

## 3. 六个阶段，按退出条件而不是功能数量推进

### M0 · 冻结旧基线，建立确定性测试骨架

**范围：** 保存旧模式入口和示例导出；增加真正的自动化测试宿主、模拟时钟、独立随机流、规则版本、命令/事件 ID；规定价格与货币单位。

**退出条件：** 相同种子和输入可回放；HHMM 转分钟、跨日跨年、订单 ID 和基本舍入测试通过；旧模式仍可单独运行。

**不做：** 多品种、漂亮 UI、银行、策略训练。

### M1 · 两个账户、一张合约，先把钱算对

**范围：** 人工脚本控制两至三个账户；完整订单状态、价格时间优先、保护价 IOC、部分成交、撤单、自成交预防、资金预留、净持仓、费用和账本。

**退出条件：** 每笔成交可追溯；现金和仓位不变量成立；重复命令不重复成交；多挂单无法超用余额；不存在“看到图表变动但没有成交事件”的现象。

**不做：** 新闻、复杂 NPC、实物交割。风险逻辑先用固定公开标记输入验证，不声称已解决抗操纵标记。

### M2 · 一个商品、12 个 NPC，完成一个交易生命周期

**范围：** 缩减现货模型、公开指数、基本代理、新闻范围与传播、风险标记、日结、保证金处置、现金到期、违约/暂停状态。

**退出条件：** 能从挂牌运行到到期；同一新闻只影响规定商品并只记一次；玩家大单确实改变盘口与成交；资金有限的做市商不会被悄悄补血；强平无流动性时不伪装完成。

**不做：** 追求所有复杂统计特征、真实农场套保、完整期现套利。

### M3 · 独立可玩终端与性能门禁

**范围：** 下单、订单、持仓、风险、账单、新闻和规则页；研究端事件回放与对账；默认规模逐步提升至全市场 32 个代理、最多 3 个活跃合约。

**退出条件：** UI 开关和帧率不改变事件结果；完整交易闭环可操作；性能预算在目标硬件被测量；多随机种子无未解释的资金/仓位错误。

**不做：** 只有图表动画、没有风险反馈的“展示 Demo”；也不因 UI 简陋而提前引入复杂前端框架。

### M4 · 星露谷适配与经营连接

**范围：** 非暂停交易终端、真实游戏时间、存读档、钱包存取、必要的动态农产品交易渠道、库存与经营计划；处理提前睡觉和时间类 Mod。

**退出条件：** 菜单时间与市场不脱节；存取款失败不复制/吞掉金币；有明确的固定价渠道边界；只有完成现货销售联动后才启用实际农场套保说明。

**不做：** 未验证的直接修改游戏时钟；未经设计的多人同步。

### M5 · 扩大期货，再开放下一资产类别

**范围：** 同标的多到期、跨期交易、多个经济品种；视需求加入仓单与实物交割、地区物流、真实期现交易。

**退出条件：** 账户、清算、数据 schema 与风险插件确实能复用；新合约规则不破坏老存档；跨市场策略记录每条交易腿及其资源约束。

**之后：** 优先试点一家有经营账本的商店股票，再考虑外汇、基金与银行，而不是同时增加五套半成品系统。

## 4. 必须先有的测试矩阵

| 编号 | 场景 | 必须满足的结果 |
|---|---|---|
| T01 | 同价两笔挂单先后提交 | 先接收者先成交；刷新盘口不改变优先级 |
| T02 | 主动订单跨三档成交 | 均价、最后价、手数与账本逐笔一致 |
| T03 | 保护价只允许部分成交 | 余量按 IOC 取消，不自动补成交 |
| T04 | 部分成交后撤单 | 只释放剩余预留，已成交持仓保留 |
| T05 | 多笔挂单占用同一资金 | 不能重复使用可用余额 |
| T06 | 自成交与重复命令 | 不产生虚假成交量或重复仓位 |
| T07 | 买入、减仓、反手、日结、到期 | 无重复盈亏；成本基准变化可解释 |
| T08 | 订单排队期间标记价变化 | 过时风险承诺被重新检查，不放行无限敞口 |
| T09 | 新闻重复投递、跨商品、延迟发布 | 实物影响只一次，范围正确，无未来信息泄漏 |
| T10 | 空盘口、单边盘口、长期无成交 | 价格/流动性状态真实，不生成伪成交 |
| T11 | 大单拉尾盘、挂撤墙、微量异常成交 | 标记/结算规则行为可审计；必要时停止新增风险 |
| T12 | 穿仓和清算基金不足 | 有明确欠款和处置状态，不凭空注资 |
| T13 | 到期指数缺失 | 停止交易并待结算，不随机选最终价 |
| T14 | 多个年份/到期并存 | 合约互不覆盖，过期不复活 |
| T15 | 保存恢复、重放、重复结算事件 | 事件哈希与账户一致，无二次扣费/结转 |
| T16 | UI 切换、帧率、加速播放 | 相同命令序列得出相同模拟结果 |
| T17 | 暂停、过夜、提前睡觉 | 不跳过风险/到期，也不在真暂停时交易 |
| T18 | 订单上限、消息积压和极端新闻 | 有界内存与确定处置，不丢关键账本事件 |
| T19 | 钱包转账中途保存/失败 | 无重复金币、无静默丢失 |
| T20 | 金额舍入、最大数量与溢出 | 无取整套利、负数量或整数溢出 |

此外对随机合法订单序列做属性测试：每个事件后验证 04 的不变量。对无效输入、损坏配置、负数、零值、非法日期和不兼容存档做拒绝测试。

## 5. 市场行为与可玩性的验证

不以“曲线像金融市场”作为唯一指标。至少记录：价差分布、盘口深度、成交率、滑点分布、资金集中度、代理收益分布、持仓集中度、强平/违约次数、现货与期货关系、新闻后的条件响应、玩家能否长期机械套利。

先进行 5 个种子 × 短周期的快速回归，再做例如 100 个种子 × 完整季节的离线实验。完整实验不在游戏主循环里跑，也不是本轮文档任务已经执行的工作。

对照实验包括：无玩家大单/有大单；无趋势者/有趋势者；无限资金仅作故障对照/有限资金；同步信息/异步信息；有无费用。所有对照都保存配置差异，不挑选单条有利曲线展示。

值得警惕的结果：单一策略总是稳赚；所有代理方向永远一致；大单影响在下一步被强制清零；所有做市商不断破产；新闻无论上下文都产生固定收益；越打开 UI 赚得越快。这些首先是机制问题，不优先用美术或更复杂随机数掩盖。

## 6. 每个里程碑应交付什么证据

提交记录、自动测试输出、固定种子与配置哈希、代表性事件日志、账本对账结果、性能报告、已知限制及 UI 截图/交互记录。

建议实验报告包含：运行时版本、构建模式、硬件、市场规模、预热方式、运行次数、P50/P95/P99、内存峰值、GC 分配、积压峰值和失败种子。所有数字区分目标与实测。
