# 02 · 价格形成与市场规则

[返回目录](README.md) · [上一页：玩家体验](01-player-experience.md) · [下一页：智能体](03-agents.md)

> 本页给出新模式的规范。旧 GBM、布朗桥模式可留作实验对照，但不得与新模式同时写入同一合约的成交价。

## 1. 先把六种“价格”分开

| 名称 | 含义和来源 | 谁能使用 | 能否直接成交 |
|---|---|---|---|
| 经济参考价值 `EconomicReference` | 当前产出、库存、需求等经济状态的内部摘要 | 经济模型；调试端 | 否 |
| 参与者估值 `AgentValuation` | 该参与者根据已有信息形成的估值和不确定区间 | 该参与者；调试端 | 否，必须先提交订单 |
| 现货指数 `SpotIndex` | 已公布的地区/品质标准化现货参考数据；早期为缩减现货模型生成 | 公共市场；结算服务 | 指数本身不是无限数量的可成交报价 |
| 最后成交价 `LastTradePrice` | 订单簿最近一笔成交的价格 | 公共市场、图表 | 过去的成交，不保证现在仍可成交 |
| 风险标记价 `RiskMark` | 按公开版本化规则选出的风险估值 | 所有账户风控和 UI | 否 |
| 结算价 `SettlementPrice` | 日终结转或到期清算使用的价格 | 清算服务、公开报表 | 否，结算不是额外一笔成交 |

买一、卖一、中间价同样独立保存。空盘口时买一或卖一为空，不用零填充。未成交的合约 `LastTradePrice` 可以为空，不得把参考价值当作第一笔成交。

普通玩家看到公开信息、自己的账户和可解释估算；看不到完整经济真值、其他账户私有估值或未来随机事件。

## 2. 最初的现货世界不需要模拟每个村民

期货必须有定义明确的标的和到期依据，但不必一开始就建设完整现货交易所。

### 第一阶段：缩减现货模型

为一个商品维护产出、可用库存、消费需求、进出口和受事件影响的预期变化。按较低频率更新，生成带时间戳、地区、品质和方法版本的现货指数。

可用下面的形式作为实验起点，而不是经济学定律：

```text
供给流量 = 本期可上市产出 + 允许释放的库存 + 净进口
需求流量 = 本期消费与加工需求
供需比 = max(需求流量, ε) / max(供给流量, ε)
指数参考 = 基准价 × 季节因子 × 供需比^弹性参数
```

供给和需求必须使用相同观察窗口、相同实物单位；不能直接拿“仓库总库存”除以“每天需求”而忽略时间单位。库存释放必须减少库存，生产增加库存，消费减少库存；边界裁剪和缺货状态需要记录原因。

指数变化可受库存缓冲和供需调整速度影响，但没有“必须逐日匀速涨到某价”的要求。未来的灾害、产出和需求尚未实现，不能提前算好整个季度的最终结算值再让 NPC 读取。

第一阶段该指数是**模拟的现货基准**，不是已经由真实现货交易形成的价格。UI 和报告必须写明这一点。

### 第二阶段：有限量的批发商与真实农场交易

为地区批发商提供有库存、有资金、有数量上限和有效期的买卖报价。玩家出售作物会改变库存、账户和未来补货需要；不能同时保留无限量固定价出口并声称完整消除了期现套利漏洞。

接入游戏时明确哪些渠道采用动态报价，哪些原版商店仍是固定报价。未统一的渠道应列为边界或禁用对应套利玩法，不要求一次修改所有游戏经济活动。

### 第三阶段：更多现货交易与地区联动

指数逐渐使用真实现货成交和可靠报价。运输时间、成本、品质折算和库存约束必须一起进入模型，不能仅用不同地区的两个价格让玩家无成本无限搬货。

## 3. 期货估值是意见，不是执行指令

NPC 可以使用现货指数、到期预期和持有成本形成参考估值：

```text
carryAnchor = SpotIndex × exp((年化利率 + 年化仓储成本 − 便利收益) × τ)
τ = 距到期的游戏天数 / 每游戏年天数
```

沿用一年 4 季、每季 28 天的当前世界设定时，分母为 112。所有配置都必须标注年化/日化单位，不重复年化。

但持有成本关系有可储存、可融资、可交易等前提。农产品腐损、交易渠道、现金结算基准、卖空限制和运输成本都会影响其适用性。因此新模式中它首先是**一类代理人的估值依据**，不是所有时刻都必须成立的无套利恒等式。

价值型代理可综合：当前现货锚、自己对到期现货的预测、持有风险的补偿和估计误差。纯期货价差交易者不持有实物时，只能称为基差/价差投机；真正期现套利必须同时记录现货腿、期货腿、融资、仓储与交割条件。

严禁把一个“必然上涨的未来目标价”公开给所有代理，然后用资金无限的套利者保证收敛。

## 4. 价格只能通过交易路径变化

标准路径：

```text
新闻或经营变化
  → 参与者更新观察与信念
  → 风控许可的订单/撤单
  → 订单簿按规则撮合
  → 成交事件
  → 更新最后成交价、成交量、账户、持仓与统计
```

订单簿改变但没有成交时，买一卖一可以变化，最后成交价不变。UI 可以展示报价移动，但不能生成伪成交、伪成交量或交易 K 线。

玩家的价格冲击已经体现在扫过了哪些价格档位、留下了怎样的盘口和持仓。**同一笔订单不能在撮合后再叠加一次 `数量 × 冲击系数` 到市场价格。** 后续影响必须来自其他参与者的响应订单。

旧 `MarketImpact` 数值叠加不进入新模式。若需要统计冲击，可记录订单前中间价、成交均价、若干模拟时间后的报价；它是分析指标，而非改价开关。

## 5. 交易所的最小规则集

### 合约身份

合约至少包含：唯一 `InstrumentId`、`CommodityId`、交易地区、品质标准、报价币种、每手实物数量、最小价格跳动、到期年份/季节/日期、交易时段、结算方式、指数 ID、规则版本。

显示名可以是“防风草·第 2 年春季”；内部 ID 必须带年份。不得让不同年份同一季节的合约互相覆盖。

### 订单类型与期限

首版只做：

- 限价单：价格满足时成交，否则剩余量进入订单簿。
- 带保护价的 IOC：立即尝试成交，超出保护价或没有对手盘的剩余数量取消。UI 可称“快速成交”，但必须展示保护价。
- 撤单：只取消尚未成交部分；已成交部分不能撤回。

日内有效与到期前有效两种期限即可。到期后任何订单都不能继续有效。止损、止盈、条件单和组合订单后续增加；止损触发也不保证成交。

### 价格—时间优先

优价优先，同价按交易所接收序号 FIFO。使用模拟时钟和单调序号，不用现实系统时间决定队列先后。

成交价采用已在簿中的被动订单价格。改单提高数量或改变价格，视为撤单重挂，失去原队列位置；只减少数量可以保留位置，但要统一实现并测试。

同一最终受益账户不得与自己成交：首版取消可能自成交的主动订单剩余部分，并记录原因。账户不能通过买卖自成交刷成交量、净值或标记价。

### 交易数量与持仓

手数为整数，每手乘数固定。买入可能是减空、开多或先减空再开多；卖出同理。首版每账户每合约只有净持仓，避免多空双向账本带来不必要的复杂度。

处理顺序、资金预留与原子成交见 [04](04-clearing-and-risk.md)。

## 6. 新闻与经济事件分层

一件事件至少有：事件实例 ID、模板 ID、发生时间、公开时间、影响商品/地区、事实变化、信息可靠度、持续方式和结束/恢复条件。

“虫害毁掉已种作物”的实物影响可以立即发生；“新店逐步开张”的消费变化可以渐进发生；两者的**信息传播速度**又可以不同。不要再让一个 `duration_days` 同时承担发生期、经营影响期、信息传播期和价格消化期四种含义。

建议拆分：`effective_from`、`economic_duration`、`recovery_rule`、`publication_time`、参与者自己的 `reaction_delay`。永久性事件也是可追踪的经济状态变化，不是无限累积、永不审查的价格加成。

事件作用范围必须保存到经济层、消息层和代理观察层。一次事件实例只进入账本一次；每个代理可以分别收到通知，但通知不能重复施加实物影响。

同一条公开新闻允许不同解释和不同反应延迟。第一版不做内幕交易特权；未来如增加信息优势，必须作为可见游戏规则，而不是让特定 NPC 偷看模拟器真值。

## 7. 日终与到期：两种不同的清算

日终结算用于结转当日盈亏和更新风险；到期结算终止合约。现实期货也区分日结、最终结算及不同交割方式，参考 [来源 R3—R5](09-sources.md)。本游戏具体采样窗口和回退规则是自定义规则，不声称复刻某交易所。

### 首版日终规则建议

使用收盘前配置窗口的有效成交量加权均价，并检查成交量、价格有效性、账户集中度和异常情况。数据不足时，使用该窗口可靠双边报价的时间加权中间价；仍不足则保留最近可信结算参考并标记“陈旧数据”，停止新增风险，按预先公布的规则处置。

窗口、最小样本、舍入和回退规则必须写入合约规则版本。不能在看到玩家盈利后临时换算法。

没有通用统计方法能保证小市场完全抗操纵。必须专门测试拉尾盘、微量成交、关联账户和大额挂撤等情境。

### 首版现金到期规则建议

使用预先公布的现货指数及采样窗口，例如到期日最后一个交易小时内等间隔指数样本的算术平均；采样时点和权重提前固定。指数缺失时进入 `SettlementPending`，等待有效数据或执行预先披露的备用规则，不临时编一个最终价格。

到期清算只改变现金、持仓和合约状态，不写入成交日志。接近到期的价格收敛主要由信息、交易和结算预期推动，不用布朗桥强行保证最后一笔成交等于结算指数。

## 8. 风险标记价不能是上帝给出的“正确价格”

首版采用简单、版本化并可审计的候选方案：从新鲜且通过质量检查的近期成交 VWAP、盘口时间加权中间价、独立现货指数推导参考中选取样本；三项可用取中位数，两项可用取均值并提高风险缓冲。

只剩一项或样本相互严重冲突时，降低置信等级、限制开新仓并采用预设的压力保证金；不把未验证参考突然替换成确定真值。最终算法必须通过 07 的操纵测试后才能用于可玩版本。

所有账户共享同一合约标记价，保证对称计价。不同账户的风险缓冲可以不同，但不能让多头用一个价格记盈利、空头用另一个价格记亏损而凭空生成资金。

## 9. 涨跌停与熔断不是修图工具

第一版优先做订单保护价、风险上限和异常数据暂停。之后如加入每日价格区间，只能限制可接受订单价格，不能把已成交价格强行裁剪，也不能让超出价格范围的强平神奇成交。

触及限价可能导致退出困难，UI 必须提示。暂停、恢复、区间调整及到期例外都使用公开规则、记录事件，并对玩家与 NPC 一致适用。

## 10. 本页的验收问题

一条曲线上的每次成交价变化是否能找到对应买卖单和成交事件？没有成交时是否仍有虚构成交量？玩家是否能从公开字段读到未来结算结果？同一新闻是否被重复计入？期现价差是否有明确解释？到期结算是否错误地改写了历史行情？

以上问题未解决时，不应继续增加股票或更多价格公式。
